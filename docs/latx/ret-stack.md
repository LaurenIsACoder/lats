# 在 RET 合并已有 pushpop 栈增量

连续 POP 仍按原偏移读取。以六次 POP 为例：

```text
前：RSP += 48；return_address = [RSP]；RSP += 8
后：return_address = [RSP+48]；RSP += 56
```

仅消费已有 pushpop 增量，不新增 ADD/SUB 延迟来源。
普通块、TU、JIT、AOT 使用同一规则。返回地址仍从客体栈读取，
flags、RAS 校验和出口顺序沿用原处理。

规则用于原 pushpop 支持上下文中的64位、末尾、无立即数 near RET，
无融合或 LOCK 前缀，实际返回地址宽度不是16位。
REP/REPNE、段覆盖和地址宽度前缀不影响本优化；操作数宽度按既有规则解析。
增量为非零且在[-2048,2039]，保证加载位移及增量加8均可由有符号12位
立即数表达，避免合并后增加指令。其他情况仍提前提交增量。

返回地址加载失败时，RSP 尚未更新；原逐指令 opt 数组记录 pending，
既有异常恢复补回该增量。加载成功后合并更新 RSP，清翻译期增量，
再走原 RAS 和出口。不增加提交后回退保证、恢复字段或 AOT 文件格式。
`pushpopret=off` 控制新生成的代码；已有 AOT 缓存按发布版本策略复用，
本次不改变缓存标识或版本。

`test-ret-stack.py` 验证真实检查、钩子和发码的边界、回退及加载顺序；
三个 C 控制程序覆盖正常返回和真实栈页故障。性能须在同一机器、同一
二进制中仅切该开关，使用完整负载耗时，不由静态指令数推算收益。
