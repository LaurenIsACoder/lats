# TU-JIT 硬件返回预测提示

## 使用方式

system 模式设置 `ras=on,rastoptp=on,tumode=jit`，用 `-latx` 命令行参数独立控制：

| `tuhras` | 行为 |
|---|---|
| `0` | 原软件 RAS、原返回布局和跳转寄存器 |
| `1` | 私有返回成员、CALL 检查布局和间接 CALL 的内联 NJC/FSHT 查找；保留原跳转寄存器，作为结构改动对照 |
| `2` | 同模式 1；有效软件 push 对应的 CALL 写入 r1，RET 使用 r1 跳转 |

`tuhras` 默认 `2`；不具备 JIT TU 页检查条件时自动回退为 `0`。

`tuhrascopy` 控制 BRANCH、JUMP 和 NORMAL 边是否复制已有 TU 的本地拓扑。
默认 `0`，只强制补全 CALL 的本地返回成员，已有 canonical 目标直接复用；
设为 `1` 时恢复完整的旧 TU 局部拓扑复制。

软件 RAS 保存并检查 guest 返回地址；硬件返回栈预测宿主返回目标。
软件检查和失败回退保留。提示只用于 64 位用户代码，覆盖 JIT TU 及其普通 TB 回退。
AOT、关闭 JIT TU 及其他代码模式保留原路径，不改变 AOT 格式或缓存版本。
必须开启 JIT TU 页跟踪及 lookup、direct、FSHT 入口检查；NJC 的隐式 FSHT 检查也计入条件。
条件不完整时打印警告，整个优化回到模式 0。

## CALL、RET 及返回布局

- 直接 CALL 使用固定 8 字节槽；初始槽为 `B cold + NOP`，近跳链接后
  写 `NOP + BL`，远跳写 `PCADDU18I + JIRL` 并设置 link 寄存器。
- 开启 NJC 时，HRAS 间接 CALL 内联现有 NJC 查找，最终 JIRL 写 r1；普通 JMP 的查找方式不变。
- TU 中的 FSHT 段放在原有中断检查分支跳过的区域，NJC 命中后直接执行 CALL；普通 TB 保留合并查找路径。
- NJC 未命中先执行原有 FSHT 快查；FSHT 也未命中时才进入 CALL 专用 C 回退。回退前恢复地址查找覆盖的客体目标，保留缓存槽、源 TB 失效检查和回填。
- NJC 关闭时，CALL 用 BL 进入原共享查找，最终保留尾跳，避免再次 push。
- RET 命中路径复用既有目标加载和跳转，把目标放入 r1，再执行 JIRL。
- 普通 TB、双 vCPU 和容量截断回退中的有效软件 push 同样执行 r1-link。

优先探索 CALL 后的私有返回成员，使 BL 的 PC+4 指向真实返回块。
保留原有成员数、页数、页锁重试限制。容量截断或普通 TB 不能保证相邻，
仍保留 r1-link 配对，但这次返回预测可能失败。
私有返回成员保留原返回块可用的分支后继，避免因缩小 TU 多出热点页检查。

直接 CALL 的检查失败出口放在 TU 尾部，正常路径调整检查方向。
直接 CALL 固定预留 8 字节槽；短距离链接时写 `NOP + BL`，使 BL 的
`PC+4` 指向槽后的私有返回 TB；长距离写 `PCADDU18I + JIRL`。
仅对可能生成 HRAS 相邻返回槽的 CALL
在 TUCHECK 前保留一个 NOP gate，其他 TUCHECK 不增加该指令；
callee 后生成且完整页覆盖允许省略检查时，直接把该 gate 改成跳到 hot slot 的 B，
不再失效或重新翻译 caller TU。
近目标、本地目标和尚未生成的目标保留 TUCHECK，并在检查后使用固定 8 字节槽；
只有已有合法目标且当前布局需要两字长跳的 CALL 才直接进入未检查 fast path。
这样避免把原先紧凑的一位 CALL 改成永久冷槽，同时保持短链接的
BL 返回地址与软件 RAS 保存的宿主返回目标一致。
目标超出 signed 36 位长跳范围视为生成配置错误，输出 source、target 和偏移后终止。
不能只根据目标起始页允许入口旁路。
同物理页重复保护扫描仅在原页锁、扫描及 RAM 保护条件已经满足时省略。
失效、重链接、重映射和 MTCC 清理沿用软件 RAS 机制。

发布 TU 前检查冷分支距离和 TBMini 长度。短条件分支超限时重试长形式；
无法容纳时走原有普通 TB 回退。TU 内无需重链接的 IRQ 回边使用固定 B，
保留中断检查，避免对齐 NOP 增加执行指令。
HRAS 的探索数组放在专用原生栈帧中；关闭模式的共享遍历保持内联，不分配该数组。
HRAS 私有成员索引和 SHBR 分析结果缓存用于减少重复分析，不写入 AOT 文件。

## 测量方法与小变化的判断

基准为 main `79c43fa8a4ffe0fa17ca0f6530a9e82dc2f1c94e`，3A6000 2.5 GHz，
相同 GCC 8.3、release O1，JIT TU、AOT off、profiler off。
使用默认 `intopt=2`，即在翻译块末尾检查中断。
启动前暂停 VM，将 vCPU 固定 CPU4，I/O 和控制线程固定 CPU2，再继续启动。
构建、传输和测量使用同一互斥锁。PMU 在 SPEC_ARM 后、发送 GO 前启用，SPEC_END 后关闭；
只统计 vCPU 线程，包含原生 helper 和少量握手开销。
启动、传输、压缩和官方输出检查在窗口外。PMU 无分时复用。

**小于 0.5% 的变化先检查抖动，不凭单点或少量同方向样本判定收益、回退。**
用同一 main 二进制在两个标签下交替运行，检查测量波动；候选版再与 main 逐轮交替比较。
保留每轮结果、先后顺序和全部软件 TLB 起止容量。
相同容量端点不能证明全程相同，不同端点也不能自动解释全部差异。
显式 `always` 配置下，使用 train 输入的六轮同一 main 自对照结果如下，正数表示第二标签更快，标签不代表候选版：

| 项目 | 配对差值范围 | 平均差值 | 说明 |
|---|---:|---:|---|
| gcc | −0.405%～+0.905% | +0.075% | 四对 TLB 端点相同，两对不同 |
| vpr | −0.649%～+0.227% | −0.160% | 一对 TLB 端点相同，五对不同 |

这些范围描述各批次观测，不能作为所有项目的固定误差界限，也不能证明候选版的小变化为零。
接近零的变化保留为待复核项；可重复的差异再定位具体代码。

PMU 0x2b/0x2d 为 jr1 类指令数及预测错误数，0x2c/0x2e 为其他 jr 类。
提示会改变分类，应同时比较 2d+2e、耗时和执行指令数。
2d/2b 包含原生函数返回，不能直接称为硬件返回栈内部命中率。
结构对照包含布局和查找改动，全部收益不能只归于 HRAS。
