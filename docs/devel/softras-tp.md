# HAMT SoftRAS：CALL 7 条、RET 6 条

`rastoptp` 在 LoongArch r2（`$tp`）中保存返回栈栈顶，保留每个 vCPU 的 512 项内存返回栈。CALL 记录七条指令，RET 命中六条；不增加栈顶、零地址或代码有效性检查。返回地址不匹配时清栈，回退 NJC，即按 guest 目标地址查找翻译代码的缓存。

选项默认关闭，仅用于 HAMT。支持普通 JIT、JIT TU 和 AOT；产品默认 TU/AOT 不因开启此选项而关闭。快速路径要求 CS64、CPL3、CS base 为零、非 16 位 CALL/RET，PC-relative 翻译未支持。r22 保留为原有临时寄存器，没有长期占用；没有单 vCPU 或 CPU0 限制。

## 生成代码

以下取自有效微基准的实际暖代码。`$s0` 为 env 映射寄存器，`$tp` 为栈顶；字段偏移取决于 CPUX86State 布局。7/6 只统计返回栈部分，guest 压栈、出栈、callee 和循环控制另计。

```asm
# CALL 已算出 guest 返回 PC，并将它压入 guest 栈；a4 仍保存此 PC
andi        $a5, $tp, 0x1ff
alsl.d      $a7, $a5, $s0, 4
stptr.d     $a4, $a7, 14048       # 保存 guest 返回地址
pcalau12i   $a4, 0
ori         $a4, $a4, 0x7b4        # 形成已链接的 host 返回目标
stptr.d     $a4, $a7, 14056
addi.d      $tp, $a5, 1

# RET 已读出 guest 返回地址到 a1，并更新 guest RSP
alsl.d      $a4, $tp, $s0, 4
ldptr.d     $a5, $a4, 14032
bne         $a5, $a1, miss
ldptr.d     $a7, $a4, 14040
addi.d      $tp, $tp, -1
jr          $a7

miss:
li.d        $tp, 0
stptr.w     $zero, $s0, 14020     # 保存的 top
stptr.w     $zero, $s0, 14016     # reset_pending
b           njc_lookup
```

间接 CALL 复用已经算出的返回 PC，callee 地址仍留在 a1；目标查找使用原有 NJC。空栈前有 `(guest PC=0, host fallback)` 哨兵，返回地址为零也进入有效查找入口，不将零判为无效或跳到空 host 指针。容量环绕或 miss 后可能连续回退，不能据此保证所有深层调用都更快。

`ldptr/stptr` 的有符号 si14 位移按四字节缩放，可访问 −32768～32764 字节。HAMT 补齐四种 PTR 指令的宽度、符号扩展和读写解码，两处 ADE 地址恢复使用相同缩放规则。

## C 边界、内核与失效

r2 在所有翻译代码中保存 top，内核 CALL/RET 跳过用户返回栈。C 运行时需要 r2 中的真实 TLS 指针：进入 C 前保存 top、消费清栈请求并恢复 TLS；离开 C 后恢复 top。r20/r21 用原生栈私有槽保护。消费请求先清活跃 r2，再保存零 top，防止中断重新发布旧值。

普通 syscall/sysret、中断和 C helper 往返保留记录。精确恢复原生 PC 的例外保留原始保存帧，包括 CALL/RET 中间状态；转回 guest 指令边界时恢复保存的 top 并消费真正失效请求。未知 top 清栈。远端 CPU 只原子设置 `reset_pending`，不直接修改另一 CPU 的活跃 r2。

`prepare` 更新 TLS 和每 vCPU 镜像，内核执行不改变用户栈所有权。首次用户初始化仅设置 top 和哨兵，不填充整个数组。清理 NJC 缓存、失效内核 TB/代码区保留用户记录；用户物理别名、用户代码区、完整缓存或 TLB 地址映射失效仍清栈。CR3/KPTI 地址空间变化采用保守处理。

## 链接与共享修复

同页目标在源 TB 发布前预翻译并链接，递归上限 16 层。其他首次链接及失效后的重链接进入冷代码，每处 CALL 固定五条：三条装载源 TB、一条 BL 调共享入口、一条 B 回 CALL。

共享入口用 80 字节原生栈帧保存 a0/a1、返回地址和六个活跃临时寄存器，再按普通 helper 约定执行 C 查找；返回后 top 为零，寄存器恢复。修复已发布代码使用 `async_safe_run_on_cpu`，让全部 CPU 退出执行后再改写；命中路径不调用它。关闭链接只改 gate，保留 payload。排队请求先核对完整/单 MTCC 清空次数，再读取 TB 指针，避免访问已回收内存。

零指令 TU 成员与下一成员共用宿主入口，不能作为独立的 RAS 目标。确认这一情况后关闭该处 CALL 的 RAS 记录，将七条记录指令的第一条改为 `b +28`，直接执行原 CALL。临时查找失败仍可重试。改写先关闭 gate、发布禁用标记，再写第一条指令；已经越过第一条的执行仍可沿完整冷路径返回。

TU（合并多个翻译块的单元）保存每个源 TB 的标签快照，区分成员内和 TU 内偏移。翻译重试前解除上一轮私有链接。AOT 保存并恢复永久禁用状态；重定位拒绝覆盖首条指令或 gate，以及缺失、重复、错位或重叠的修复记录。格式为 24，旧缓存重新生成。共享入口随静态代码生成、复制和重定位，不增加运行期地址表。

完整清空后，各 MTCC 分别保留静态前缀并领取不同代码区域，其他 context 不会从同一位置生成代码。

## 独立的失效入口处理

HAMT 的 64 位 CPL3 可执行 TB、TU/AOT 成员失效时，将入口第一条改为 `0x1`。旧 RAS/NJC 指针进入保留指令例外后，确认失效 TB 身份，恢复 guest PC 与 a1，再跳到查找入口。已经完成的 RET/RSP 不重放，也不注入 guest page fault。

该功能不受 `rastoptp` 控制。每 vCPU 有独立入口页，保存映射的 GPR、MMX/XMM、x87 及 FCSR；其他非法指令仍使用原错误处理。未激活 AOT 模板、共用入口的零长度 TU 成员不写入失效指令；已执行并失效的 AOT TB 不重新激活。代码回收保留已有 exclusive 保护。

## 验证结果

以下性能基于 main `0936812` 加本 PR。同一被测二进制在 3A6000 2.0GHz、CPU4（同核线程 CPU5）下测量；控制线程 CPU2。默认 JIT TU，测试显式关闭 AOT，其余产品默认参数保留。九轮轮换模式、交替 100M/400M 次，以 PMU 计数差计算每次完整 CALL/RET 循环，再取中位数。

| case | NJC cycles | 原 SoftRAS | r2 SoftRAS | 相比 NJC 减少 |
|---|---:|---:|---:|---:|
| direct | 9.064 | 14.359 | 8.061 | 11.07% |
| indirect 单目标 | 42.309 | 15.842 | 10.075 | 76.19% |
| indirect 四目标 | 14.099 | 16.306 | 13.110 | 7.02% |

三项中位数均优于 NJC。单目标差异包含避开 NJC 哈希冲突，不能解释为纯命中延时差。216 条输出与原生一致，PMU 未复用；NJC/原 SoftRAS/r2 模式分别有 54/54/54 个暖 TU 成员，代码字节和元数据前后相同。后台预算事先指定为 0.5%，固定竞争线程仍拒绝；该预算不代表误差上限。接受测量均通过检查，汇总从原始计数重新计算。
